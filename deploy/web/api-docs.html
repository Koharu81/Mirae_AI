Mirae AI API

처음 API를 사용하는 개발자도 그대로 복사하고 수정해서 사용할 수 있도록, 호출 주소부터 인증·요청·응답·실전 예제까지 정리한 공식 개발자 문서입니다.

이 문서에서 제공하는 것

Mirae AI를 실제 프로그램에서 호출하는 방법을 설명하는 수동 제작 개발자 문서입니다. 주소, 인증, 요청 형식, 응답 구조, 예제 코드를 순서대로 따라 하면 Discord 봇이나 웹앱에서 바로 연결할 수 있습니다.

Base URL: https://api.koharu.live/v1
인증: Authorization: Bearer YOUR_API_KEY
  • POST /v1/chat/completions · AI에게 메시지를 보내고 답변을 받는 핵심 API
  • GET /v1/models · 사용할 모델 ID 확인
  • GET /health · 서버 상태 확인

AI가 작동하는 핵심 호출은 POST /v1/chat/completions입니다. 웹사이트, Discord 봇, Python 프로그램, Node.js 프로그램 등 어떤 클라이언트에서도 이 엔드포인트를 호출할 수 있습니다.

import nextcord
from nextcord.ext import commands
import aiohttp

API_KEY = "YOUR_API_KEY"
API_URL = "https://api.koharu.live/v1/chat/completions"
bot = commands.Bot(command_prefix="!", intents=nextcord.Intents.default())

@bot.command()
async def ask(ctx, *, prompt: str):
    payload = {"model":"Mirae-Qwen2.5-1.5B-Instruct","messages":[{"role":"user","content":prompt}]}
    headers = {"Authorization":f"Bearer {API_KEY}","Content-Type":"application/json"}
    async with aiohttp.ClientSession() as session:
        async with session.post(API_URL,headers=headers,json=payload) as response:
            data=await response.json()
    await ctx.send(data["choices"][0]["message"]["content"])

웹앱을 직접 만들 때의 핵심 구조

Mirae AI를 사용하는 웹앱을 만들 때는 브라우저에 API 키를 넣어 공개하지 않는 것이 중요합니다. 권장 구조는 사용자 브라우저 → 개발자가 만든 백엔드 → Mirae AI API입니다.

사용자 입력
   ↓
내 웹앱 백엔드
   ↓  Authorization: Bearer YOUR_API_KEY
POST https://api.koharu.live/v1/chat/completions
   ↓
Mirae AI 모델
   ↓
choices[0].message.content
   ↓
내 백엔드가 브라우저에 답변 전달

API 키는 HTML, React, Next.js 클라이언트 코드에 직접 넣지 말고 서버 환경 변수에 저장하세요.

웹 검색

Mirae는 모든 질문을 검색하지 않습니다. 단순 대화는 검색하지 않고, 명시적인 검색 요청 또는 최신·현재 정보가 필요한 질문에서 검색을 시도합니다. 검색 결과에 없는 세부사항은 사실처럼 만들어내지 않도록 프롬프트에 제한을 둡니다.

스트리밍

/chat/stream은 SSE를 사용합니다. 웹앱은 질문 분석, 정보 확인, 답변 생성, 제목 정리, 완료 같은 높은 수준의 진행 상태를 표시합니다.

스킬과 메모리

로그인한 계정은 설정에서 HTTP 스킬을 등록하고 실행할 수 있으며, 자연어 프롬프트로 스킬 구성을 요청할 수도 있습니다. 메모리는 사용자가 직접 저장한 내용을 다음 대화의 컨텍스트에 참고 정보로 제공합니다.

Mirae 플러그인 확장 API

플러그인은 사용자가 등록한 외부 HTTPS API를 Mirae에 연결하는 확장 방식입니다. 설정에서 플러그인을 등록한 뒤 허용할 권한을 선택합니다. 플러그인은 허용된 권한만 컨텍스트로 전달받습니다.

POST /plugins/{plugin_id}/invoke

{
  "input": {
    "query": "사용자 입력"
  }
}

플러그인 서버에는 다음과 같은 JSON이 전달됩니다.

{
  "input": {"query": "사용자 입력"},
  "plugin": {"name": "예제 플러그인", "version": 1},
  "permissions": ["network", "profile.read"],
  "context": {
    "profile": {"name": "...", "bio": "...", "birth_date": "..."}
  }
}
  • network · 외부 플러그인 API 호출에 필요합니다.
  • chat.read · 사용자가 명시적으로 허용한 경우 대화 컨텍스트를 전달합니다.
  • profile.read · 이름·자기소개·생일을 전달합니다.
  • memory.read · 저장된 메모리를 전달합니다.

Mirae 서버는 플러그인 URL의 로컬·사설 네트워크 주소를 차단하고 요청 시간과 응답 크기를 제한합니다. 권한을 선택하지 않은 데이터는 플러그인 컨텍스트에 넣지 않습니다.

API 호출 순서

  1. API 키를 발급합니다. Mirae AI의 API 키 페이지에서 키를 한 번 발급합니다.
  2. 키를 안전하게 저장합니다. Discord 봇이라면 환경 변수에 저장하고 소스 코드에 직접 넣지 않습니다.
  3. 엔드포인트를 호출합니다. POST https://api.koharu.live/v1/chat/completions을 사용합니다.
  4. 인증 헤더를 넣습니다. Authorization: Bearer YOUR_API_KEY 형식입니다.
  5. JSON을 전송합니다. 최소한 model과 messages를 넣습니다.
  6. 응답을 읽습니다. AI 텍스트는 choices[0].message.content에 있습니다.

최소 요청 예제

POST https://api.koharu.live/v1/chat/completions
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json

  "model": "hf.co/Qwen/Qwen2.5-3B-Instruct",
  "messages": [
    {
      "role": "user",
      "content": "안녕하세요"
    }
  ]

Discord 봇에서의 권장 구조

Discord 이벤트를 받은 뒤 Mirae API를 호출하고, 응답에서 텍스트만 추출해 Discord 메시지로 보내면 됩니다.

Discord message
      ↓
ask_mirae(prompt)
      ↓
POST /v1/chat/completions
      ↓
choices[0].message.content
      ↓
Discord reply

봇 코드에서 API 호출이 성공하는지 먼저 확인한 뒤 Discord 응답 표시를 붙이면 문제를 분리하기 쉽습니다.

응답에서 사용해야 하는 값

경로용도
choices[0].message.content최종 AI 답변
model실제로 표시된 모델 ID
sources웹 검색이 사용된 경우의 검색 결과
choices[0].finish_reason생성 종료 상태

웹 검색이 필요한 경우

API는 인사와 일반적인 대화에서 불필요한 웹 검색을 하지 않도록 동작합니다. 최신 정보, 현재 상태, 명시적인 검색 요청처럼 최신 데이터가 필요한 질문은 검색을 시도할 수 있습니다.

검색 결과는 응답의 sources 배열에 포함될 수 있습니다. 애플리케이션에서 이 배열을 표시하고 싶다면 제목과 URL을 사용하면 됩니다.

모델을 하드코딩하기 싫다면

먼저 GET /v1/models를 호출해 계정에서 사용할 수 있는 모델 ID를 확인한 다음 그 값을 model에 넣을 수 있습니다.

GET https://api.koharu.live/v1/models
Authorization: Bearer YOUR_API_KEY

자동 웹 검색

Mirae는 웹 검색을 켜라고 말하지 않아도 질문의 최신성·외부 정보 필요성을 판단합니다. 최신·현재·가격·뉴스·일정·공식 정보처럼 외부 자료가 필요한 질문은 자동으로 검색을 시도하며, 단순 인사나 일반적인 개념 질문은 검색하지 않습니다.

이미지 생성 API

POST /v1/images/generations

Authorization: Bearer YOUR_API_KEY
Content-Type: application/json

{
  "model": "mirae-image",
  "prompt": "밤하늘 아래의 작은 오두막"
}

응답의 data[0].url은 표시용 data URL이고 data[0].b64_json에는 PNG Base64가 들어 있습니다.

채팅에서 이미지 요청

POST /v1/chat/completions에 자연어로 이미지 생성을 요청하면 이미지 생성 의도를 판별하고 images 배열을 함께 반환합니다.

스트리밍

POST /chat/stream

SSE 이벤트 stage, search_query, sources, delta, conversation, done, error를 사용합니다.

비전

POST /vision

로그인 세션에서 이미지를 업로드해 이미지 분석을 요청할 수 있습니다.

실패했을 때 확인 순서

  1. HTTP 상태 코드가 401인지 확인합니다. 401이면 API 키 또는 Authorization 헤더 문제입니다.
  2. 422라면 요청 JSON의 필드 이름과 자료형을 확인합니다.
  3. 200인데 답변이 비어 있다면 choices와 message.content를 확인합니다.
  4. timeout이면 클라이언트 timeout을 충분히 길게 설정하고 다시 요청합니다.
  5. Discord 봇에서만 실패한다면 같은 API 키와 같은 JSON을 Python/cURL에서 먼저 테스트합니다.
